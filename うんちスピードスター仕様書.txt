うんちスピードスター 仕様書（完全版）

================================
1. ゲーム概要
================================

タイトル: うんちスピードスター
ジャンル: 反応速度＋フェイント系リアクションゲーム
雰囲気: 馬鹿らしいけど白熱する／短時間で盛り上がる

モード:
- ひとりであそぶ
- みんなであそぶ（通信対戦）
- ハイスコア


================================
2. 共通ルール
================================

- 画面中央に単語が1つ表示される。
- 「うんち」が出たらタップする。
- 「うんち」以外（例：らんち、うんちょ、うんちん等）でタップすると「お手つき（ペナルティ）」。
- 難易度は以下で変化する：
  - 表示間隔の速さ
  - 緩急の付き方
  - フェイント率
- 単語は固定リスト（全レベル共通）を使用する。


================================
3. 単語リスト（固定）
================================

初期は約10個程度。  
動作確認後に約20個程度まで増やす想定。

例（初期候補）:
- うんち（正解）
- らんち
- うんちょ
- うんちん
- うんつ
- うんちー
- うんちっ
- うんちまん
- うんちょす
- うんちんぐ
- うんちょる
- うんちょん

正解判定:
- 文字列が完全一致で「うんち」のときのみ正解。


================================
4. 難易度設計
================================

共通仕様:
- どのレベルも表示間隔の上限は 2200ms。
- レベル差は以下でつける：
  - 最低表示間隔（速い時の速さ）
  - 緩急の付き方（ランダム幅）
  - フェイント率（うんち以外が出る確率）

LEVEL 1：EASY
- 表示間隔: 1500〜2200ms
- 緩急: 弱い（ほぼ一定）
- フェイント率: 20%

LEVEL 2：NORMAL
- 表示間隔: 1000〜2200ms
- 緩急: 中（少し速くなったり遅くなったり）
- フェイント率: 35%

LEVEL 3：HARD
- 表示間隔: 600〜2200ms
- 緩急: 強い（急に速くなる）
- フェイント率: 50%

LEVEL 4：CHAOS
- 表示間隔: 300〜2200ms（完全ランダム）
- 緩急: 最大（速→遅→速→遅）
- フェイント率: 70%


================================
5. ひとりであそぶ
================================

ルール:
- 5回勝負。
- 各回、「うんち」をタップできて初めてその回が終了。
- 「うんち」が表示されてからタップするまでの時間を計測。
- 5回分の合計時間がスコアとなる。
- お手つき1回につき +0.5秒加算（調整可能）。

難易度進行（例）:
- 1回目: LEVEL 1
- 2回目: LEVEL 1
- 3回目: LEVEL 2
- 4回目: LEVEL 3
- 5回目: LEVEL 4

UI:
- 画面上部に各回のタイムとお手つき回数を表示。
- 最下部に合計タイムを表示。
- 画面中央に単語を大きく表示。
- 画面全体がタップ判定領域。
- 正解時: 画面が緑フラッシュ。
- お手つき時: 画面が赤フラッシュ。

ハイスコア:
- 合計タイムの最小値をハイスコアとして保存。
- タイトル画面の「ハイスコア」から参照可能。

効果音（あり）:
- 単語が出た時
- 正解時
- お手つき時
- 勝利が決まった時
- ハイスコア更新時


================================
6. みんなであそぶ（通信対戦）
================================

人数:
- 2〜4人でプレイ可能。

勝利条件:
- 先に 5点 を取ったプレイヤーの勝ち。

得点ルール:
- 「うんち」を最速で正しくタップしたプレイヤー: +1点。
- 誤タップ（うんち以外をタップ）: −1点。
- 正解が複数同時の場合: 最速の1人だけ +1点。

難易度変化:
- 誰かがポイントを取るたびに difficultyLevel が 1〜4 の中からランダムで変更される。
- それに応じて表示間隔・緩急・フェイント率が変化。

ルーム作成方式:
1. タイトル画面で「みんなであそぶ」を選択。
2. 人数選択画面で以下から選ぶ：
   - 2人であそぶ
   - 3人であそぶ
   - 4人であそぶ
3. 選択後、ランダム6桁英数字の roomId を生成。
4. Firebaseに以下を保存：
   - maxPlayers（2〜4）
   - playerCount（現在人数）
   - state（"waiting" → "starting" → "playing" → "finished"）
5. maxPlayers に達したら自動でゲーム開始。

プレイヤー名の扱い:
- 毎回名前入力可能。
- 名前未入力の場合はランダム名（例: Player123）を自動付与。

ゲーム進行（1ラウンドの流れ）:
1. サーバー（Cloud Functions）が以下を決定し、Firebaseに書き込む：
   - currentWordIndex（単語のインデックス）
   - difficultyLevel（1〜4）
   - nextInterval（次の表示までの時間）
2. 各クライアントは nextInterval ミリ秒後に、
   フロント側の固定リストから currentWordIndex の単語を表示。
3. プレイヤーがタップすると、Firebaseに以下を送信：
   - tapTime = Date.now()
   - tapWordIndex = currentWordIndex
4. Cloud Functions が全プレイヤーの tapTime と tapWordIndex を判定：
   - 単語が「うんち」かどうか（正解／誤タップ）
   - 最速プレイヤーの決定
   - スコア更新（+1 / −1）
5. 誰かが 5点 に到達したら：
   - state = "finished"
   - winner = 該当プレイヤー
6. 勝者表示後、一定時間経過でルーム削除（任意）。

UI:
- 上部: 各プレイヤーの名前＋点数を横並び表示（2〜4人対応）。
- 中央: 単語を大きく表示。
- 下部: 現在の難易度（EASY / NORMAL / HARD / CHAOS）を表示。
- 画面全体がタップ判定領域。
- 正解時: 緑フラッシュ＋スコア更新。
- 誤タップ時: 赤フラッシュ＋−1点。

効果音（あり）:
- 単語が出た時
- 正解時
- お手つき時
- 勝利が決まった時

8. ハイスコア保存仕様
================================

ひとりであそぶ:
- 合計タイムの最小値をハイスコアとして保存。

保存先:
- ローカルストレージ（端末ごと）
- Firebase（ユーザー名＋スコア）  
  → 将来的にランキング表示などに利用可能。


================================
9. Firebase利用方針（概要）
================================

ひとりであそぶ:
- 基本ローカル処理。
- ハイスコアを Firebase に保存する場合あり。

みんなであそぶ:
- Realtime Database:
  - ルーム情報（roomId, maxPlayers, playerCount, state）
  - プレイヤー情報（name, score）
  - difficultyLevel
  - currentWordIndex
  - nextInterval
- Cloud Functions:
  - タップ判定（正解／誤タップ）
  - 最速プレイヤー判定
  - スコア更新
  - 難易度変更
  - 勝利判定
  - ルーム削除（任意）


================================
10. 実装メモ（Gemini向け補足）
================================

- 単語リストはフロント側の固定配列で管理。
- 難易度ごとの設定はオブジェクトで持つと実装しやすい例：

  const difficultySettings = {
    1: { min: 1500, max: 2200, fakeRate: 0.2 },
    2: { min: 1000, max: 2200, fakeRate: 0.35 },
    3: { min: 600,  max: 2200, fakeRate: 0.5 },
    4: { min: 300,  max: 2200, fakeRate: 0.7 }
  };

- 正解判定は「表示中の単語 === 'うんち'」で行う。
- プレイヤー名は入力欄を用意し、未入力ならランダム名を生成する。
- 効果音はイベントごとに別の音を割り当てる（正解／お手つき／表示／勝利／ハイスコア更新）。


================================
11. Firebaseバージョン指定（重要）
================================

本ゲームの実装は **Firebase v9 modular** を使用する。

理由:
- GitHub Pages との相性が良い
- 情報量が多く、調べやすい
- Gemini が v9 のコード例を返しやすい
- v10 とほぼ同じ書き方で、安定している

import例:
import { initializeApp } from "firebase/app";
import { getDatabase, ref, set, onValue } from "firebase/database";
